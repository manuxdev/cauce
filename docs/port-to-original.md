# Port to original

Features built on `dev` that should later go to the `original` branch as well. Port them only when asked, and keep
what makes `original` special: its providers, their sign-in flows and their provider features.

Store-only commits (removing providers or lyrics sources, the bundle id, store copy) never go to `original`.

| Commit | Feature | Notes |
|---|---|---|
| `f6e7732` | Play next, add to queue, queue saved at once, scrolling track options sheet | Touches the bridge, so regenerate it with `flutter_rust_bridge_codegen generate` after porting. The track options sheet in `original` also has its provider rows |
| `7097bdf` | Lyrics from the Subsonic server: `SubsonicLyrics` registered as the `server` lyrics group, default order `lrc`, `server`, `lrclib`, and saved orders without `server` get it at its default place | `original`'s lyrics groups also include `provider`, so merge the default order there (`lyricsSourceGroups` in `app_prefs.dart` and `GROUPS` in `lyrics_shelf.rs`) rather than taking this one as is |
| `6939923` | Lyrics sources can be turned off: a switch on each row of the lyrics source list, kept as `lyricsSourcesOff` in `app.json` (unknown names ignored, missing key means all on), Dart sends only the sources left on (`askedLyricsSources`), and Rust's `search_lyrics` asks only the services in the groups it is given | `original` also has the `provider` group; it gets a switch the same way, with no extra change, since it is in `lyricsSourceGroups` and `GROUPS` |
| `72796a6` | Downloads stay in sync: turning on "download likes", app start and coming back online queue the likes not downloaded yet; downloading an album or playlist keeps it (`kept.json` beside `downloads.json`, missing file means none kept), and opening it or a catch-up downloads what it gained. Removing all its downloads, or "Remove download" on its page, stops keeping it. Tracks still in a kept collection never go stale | Touches the bridge, so regenerate it after porting. Catch-up walks `accounts.connected` and calls `savedTracks` and `collectionTracks` per provider: check each of `original`'s providers answers both (and refuses cleanly when it cannot download, since `download_missing` stops on that), and that the ones whose likes or playlists are very large or rate-limited cope with a fetch on every start |
| `8669d36` | Manual offline mode: an "Offline mode" switch in Downloads and storage, kept as `offlineMode` in `app.json` (missing key means off). `online` in `status_band.dart` is now derived (`deviceOnline && !offlineMode`) and the native callbacks feed `deviceOnline`. The core hears the effective state through the new `set_offline` bridge call, kept on the vault: Subsonic streams only what the vault holds, the download pump waits, `api()`, `restore` and `sign_in` refuse, and only local lyrics are asked. Uncached artwork is not fetched. The band reads "Offline mode is on" | Touches the bridge and the vendored `music` crate (`vault.rs`, `subsonic/playback.rs`), so regenerate it after porting. Each of `original`'s other providers needs the same "stream only from the vault when offline" check in its fetch `load`, or it will still stream while offline mode is on |
| `10c99fb` | Manage downloads: a "Manage downloads" row in storage opens the downloads grouped by kept album or playlist, then "Other tracks", largest first, with sizes read from the vault files (`Player::download_size`, `Shelf::size`). A track in two kept collections shows in both and counts once in the total. Deleting a group stops keeping it and removes its tracks, except those another kept collection holds and, with "download likes" on, liked ones. Kept collections now store `name` and `cover` in `kept.json` (missing means none; an album falls back to its first track's) | Touches the bridge (`download_groups`, `remove_kept_collection`, `keep_collection` gains `name` and `cover`) and the vendored `music` crate (`engine.rs`, `lib.rs`, `vault.rs`), so regenerate it after porting. A provider of `original` whose player does not use the vault `Shelf` reports 0 bytes until it implements `download_size` |
